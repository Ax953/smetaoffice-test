# SmetaOffice: шлюз передачи продажи в проект

Дата: 14.06.2026
Статус: локальная версия для проверки.

## Правило

SmetaOffice не должен создавать проект напрямую из продажи.

Правильная цепочка:

```text
Bitrix Deal
→ SalesDeal
→ ProjectHandoff
→ подтверждение производства
→ Project
```

## Статусы ProjectHandoff

| Статус | Смысл |
|---|---|
| `draft` | Не хватает данных для передачи в производство |
| `ready` | Данные собраны, можно проверить производством |
| `accepted` | Производство приняло сделку, проект можно создавать или связывать |
| `transferred` | Проект уже создан или связан |

## Важное отличие

`accepted` не означает, что проект создан.

`accepted` означает только, что РП / ГИП / управляющий со стороны производства принял сделку и готов отвечать за её запуск.

Созданным проектом считается только:

- есть `projectId`;
- или `ProjectHandoff.status = transferred`;
- или `SalesDeal.projectHandoffStatus = transferred`.

## Что изменено

- Вкладка `Продажи / Лиды` → `Передача в проект` стала отдельным шлюзом.
- На экране показана цепочка `Bitrix Deal → SalesDeal → ProjectHandoff → подтверждение производства → Project`.
- Добавлена сводка по статусам шлюза.
- Добавлено действие `Подтвердить производство` для ролей производства и верхнего доступа.
- Продажи больше не считаются связанными с проектом на статусе `accepted`.
- Геймификация засчитывает передачу только после `accepted` или `transferred`, а не на статусе `ready`.
