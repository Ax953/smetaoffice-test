Дата проверки: 14.06.2026

Статус: локальная версия для проверки, не официальный релиз.

## Цель

Добавить слой управления продажами в SmetaOffice без создания второй CRM.

Bitrix24 остается источником лидов, стадий, менеджеров и первичной CRM-логики. SmetaOffice показывает только управленческий контроль:

- теплые и квалифицированные сделки;
- SLA ответа;
- следующий шаг менеджера;
- готовность передачи в проект;
- эскалации;
- отчетность по менеджерам, регионам и направлениям;
- геймификацию отдела продаж.

## Первый слой сущностей продаж

| Сущность | Назначение | Проверка |
|---|---|---|
| `SalesDeal` | Управленческая сделка SmetaOffice поверх лида/сделки Bitrix24. Bitrix24 остается источником, SmetaOffice не становится второй CRM | PASS |
| `SalesActivity` | Действия по сделке: звонок, встреча, КП, комментарий, следующий шаг. Хранится отдельной коллекцией и привязывается к `dealId` | PASS |
| `ProjectHandoff` | Передача сделки в проект после договора/аванса. Теперь API формирует системный чек-лист только для подходящих стадий, а не для каждой сделки подряд | PASS |
| `SalesEscalation` | Риски и нарушения. Теперь API формирует системные эскалации по красным/желтым сделкам и считает их в отчетности | PASS |

Важное уточнение: `ProjectHandoff` и `SalesEscalation` могут быть явными записями в JSON-базе или системно рассчитанными из `SalesDeal`. Это первый слой MVP, без записи обратно в Bitrix24.

|---|---|
| Реальная запись обратно в Bitrix24 | Запрещено на этом этапе, чтобы не сломать текущую логику SmetaGO |
